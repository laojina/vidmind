# VidMind 后端面试问答

以下答案以仓库代码为准，不包含未经测量的性能提升、独立开发经历或供应商费用结论。准备时应能打开对应类讲清方法和状态流转。风险细节见 [工程清单](engineering-risks.md)。

## 1. 这个项目的核心价值是什么？

把长视频转成可检索的语音与画面文字证据，围绕目标生成结构化结果。Java 后端负责上传、异步任务、多模态解析、检索、受控 Agent 和恢复；Vue 是展示与交互入口。不能把项目讲成仅调用一次大模型总结视频。

追问：为什么不直接把全部转写给模型？长上下文成本和信息密度不稳定，当前通过 5 分钟知识块和 TopK 检索控制输入；这也会遗漏全局信息，需要召回评估。

## 2. LangChain4j 实际做了什么？

`DeepSeekUtils` 使用 `OpenAiChatModel` 实现 OpenAI 兼容模型接入，通过 SystemMessage/UserMessage 发起调用。Planner、Executor、Critic 是 `AgentLoopService` 的编排方法，RAG 是自研检索服务，并没有采用整套框架 Agent 工具调用或内置 RetrievalAugmentor。

追问：为何选择自研？可以把模式、证据、预算和 Checkpoint 放在明确的业务边界；代价是要自行维护结构解析、重试与评估，不能直接宣称比框架更好。

## 3. 一次任务怎么经过 RocketMQ？

Controller 校验用户归属 → Dispatch 构造内容指纹/目标摘要/模式身份 → Redis 占位和配额 → MQ 投递 → Consumer 抢锁、检查复用、执行 → 保存状态与结果 → 发布事件。消息队列解决 HTTP 解耦与积压，不保证整个系统 exactly-once。

追问：Redis 成功但 MQ 失败怎么办？当前回滚占位；发送成功但确认失败仍有重复窗口，下一步采用任务表或 Outbox，消费端保持幂等。

## 4. 为什么同时要锁和幂等键？

锁限制同时执行，completed 键/Checkpoint 允许复用产物，active 键抑制重复提交。三者生命周期不同。键由 `AnalysisTaskKeys` 统一生成，目标带模式以避免串结果。

追问：锁竞争消息直接 ACK 有什么问题？同一视频的不同 mediaId 未必收到各自结果；应以并发集成测试验证等待、重投和结果扇出策略。

## 5. 分片上传如何断点续传？

uploadId 元数据与已上传分片编号在 Redis，分片在 MinIO。先成功保存分片再登记编号，客户端查询完成集合后续传。合并时按编号复制到临时文件并流式计算 MD5，不需要把整个视频读进内存。

追问：合并可否保证只插一条媒体？不能。数据库保存与 Redis completed 标记之间有失败窗口，应加持久化 uploadId 唯一键。分片重传与合并也需协调。

## 6. MD5 可以当安全保证吗？

当前是内容复用指纹，不用于密码或身份认证。MD5 存在碰撞风险；对不可信上传，可改 SHA-256，并结合文件大小、媒体归属与模型版本控制复用。密码使用加盐 PBKDF2，会话 token 使用随机字节并以 SHA-256 摘要作为缓存键。

## 7. ASR 与 OCR 如何融合？

语音分段与关键帧分支在独立有界执行池上运行；关键帧采用场景变化及周期采样，感知差异哈希去重，Tesseract OCR 后按 60 秒窗口与语音合并。单分支失败可降级，两路都失败则任务失败。

追问：能定位到精确字词时间吗？当前主要是窗口级证据，不等于逐字词强制对齐。快闪字幕和重复画面可能被采样/去重漏掉。

## 8. 混合检索怎样打分？

`VideoEvidenceRetrievalService` 将块级语义、关键词、视觉文本加权，再对子片段排序；默认 TOP_K=3。Qdrant 查询按 mediaId 过滤，失败时用已有内存向量余弦与关键词降级；Embedding 也失效时语义通道减少。

追问：为什么权重合理？当前是工程启发值，没有实验数据证明最优。需要固定标注集测 Recall@K、相关性、无答案场景，再调权重和阈值。

## 9. Agent 怎么判断结束？

Critic 通过或达到轮数上限结束，默认两轮；代码还校验计划、产物结构和证据。存在时长、估算 token 与可选估算费用预算。两轮不通过时可以返回带警告结果，不应说所有结果都通过质量校验。

追问：预算是否限制全流水线？Agent 预算作用于编排与模型调用；下载、ASR/OCR 有独立超时，不是一个统一的任务截止时间。

## 10. 证据校验能防幻觉吗？

检查引用来源、时间窗和原文子串，并要求绑定结论；本次修复了未知来源标签可通过的边界。它能拦截部分伪引用，但原文存在并不意味着结论正确，仍需语义判断、无答案策略与人工抽查。

追问：时间边界怎么定义？片段采用左闭右开区间，endMs 对应下一个片段；已有回归测试覆盖右边界。

## 11. Checkpoint 为什么落 MySQL 还要 Redis？

MySQL 提供持久恢复真源，Redis 提速。Repository 在数据库事务提交后更新缓存，避免未提交数据被读到。上下文与块是媒体级，计划和结果按媒体/目标/模式隔离；Executor 草稿可以让恢复从 Critic 接着走。

追问：清理失败怎么办？当前部分清理是尽力执行，仍可能残留索引或对象，生产应采用可重试清理队列和引用计数。

## 12. 为什么 SSE 而不是 WebSocket？

任务阶段主要是服务端单向推送，SSE 足够。Redis PubSub 将事件广播到各实例，本地保存连接集合。PubSub 不持久化，不保证断线重放，客户端必须通过状态查询补齐；还需要连接配额与心跳。

## 13. 大模型重试如何避免费用失控？

有限次数重试、只重试暂态错误、超时结合预算、有界调用线程池。MQ 重投可能再调用模型，Checkpoint 减少重复工作但不能完全防止失败窗口中的重复费用。Telemetry 是估算而非账单，应优先使用供应商 usage 和累计任务预算。

## 14. 外链视频下载有什么安全边界？

只允许 HTTP/HTTPS，对首次 DNS 地址检查回环、私网和部分保留段；ProcessBuilder 参数列表减少 shell 注入。但子进程会重解析和跟随重定向，应用校验不足以封住 SSRF。需要网络隔离和出口策略。

## 15. 为什么 v1.0.0 仍然列风险？

Tag 标记明确源码快照，不等于生产认证。本次后端测试和前端构建通过，但没有长视频性能报告和外部服务全链路故障注入。面试应主动区分已实现、已测试和下一步计划。

## 16. 面试官质疑提交历史怎么办？

如实解释早期是完整基线导入，后续包含 UI、配置、兼容性及本次源码清理和边界修复。提交说明按真实 diff 整理，保留作者和日期，不把导入记录说成逐天从零开发。展示具体方法、回归测试与失败边界比人为营造日期更有说服力。

## 17. 当前最优先修什么？

优先上传完成持久幂等、消息投递一致性、同内容多媒体任务结果传播和下载执行器网络隔离。再解决向量维度迁移、上下文单片段超预算、孤儿对象清理和 SSE 配额。每项都应先构造故障/边界测试，不能只改 README。
